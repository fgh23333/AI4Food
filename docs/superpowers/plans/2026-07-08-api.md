## 步骤 2：query.ts 纯函数（TDD 核心）

### 2.1 先写测试 `tools/tests/server/query.test.ts`

用 Vitest，构造固定 `IndexEntry[]` 样本（含 open/closed、不同 city/cuisine/price、有/无 rating、tags）。覆盖：

- `filterBy(entries, {city})` 单条件
- 组合条件（city + cuisine + price）
- `search(entries, q)` 匹配 name/address/cuisine/tags，大小写不敏感
- `sortBy(entries, 'name'|'rating'|'updated')`，rating/updated 缺失值排末尾
- `paginate(entries, {limit, offset})` 边界（offset 超出返回空、limit 截断、默认值）
- `buildMeta(entries)` 返回 total/open/cities/cuisines/price_levels

跑 `pnpm test` 确认失败（query.ts 尚不存在）。

## 步骤 4：改造 hono.ts + 集成测试

### 4.1 `tools/src/server/hono.ts`

```ts
import { Hono } from 'hono'
import type { DataLoader } from './loader'
import { applyQuery, buildMeta } from './query'

export function createApp(loader: DataLoader): Hono {
  const app = new Hono()

  app.get('/api/restaurants', async (c) => {
    const all = await loader.loadAll()
    const params = { /* 从 c.req.query() 解析，带类型转换与校验 */ }
    const { data, pagination } = applyQuery(all, params)
    return c.json({ data, pagination })
  })

  app.get('/api/restaurants/:id', async (c) => {
    const id = c.req.param('id')
    const all = await loader.loadAll()
    const found = all.find((r) => r.id === id)
    if (!found) return c.json({ error: 'not found' }, 404)
    return c.json(found)
  })

  app.get('/api/meta', async (c) => {
    const all = await loader.loadAll()
    return c.json(buildMeta(all))
  })

  // 预留：下一期接入 LLM
  // app.post('/api/ai/recommend', ...)

  return app
}
```

参数解析注意：`price`/`limit`/`offset` 要转 number 且校验范围，非法值返回 400。

## 步骤 5：改造 cli.ts `server` 命令

```ts
case 'server': {
  const { serve } = await import('@hono/node-server')
  const app = createApp(nodeLoader)

    console.log(`API 运行于 http://localhost:${info.port}`)

}
```

## 步骤 6：Worker 入口 + 配置

### 6.1 `tools/src/server/worker.ts`

```ts
import { createApp } from './hono'
import { createWorkerLoader } from './loader'

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const app = createApp(createWorkerLoader(env.ASSETS))
    return app.fetch(request)
  },
}
```

> `Env` 接口含 `ASSETS: Fetcher`，由 `wrangler types` 生成到 `worker-configuration.d.ts`。

### 6.2 `tools/wrangler.jsonc`

```jsonc
{
  "name": "ai4food-api",
  "main": "src/server/worker.ts",
  "compatibility_date": "2026-07-08",
  "assets": {
    "directory": "../../dist",
    "binding": "ASSETS"
  }
}
```

### 6.3 `tools/tsconfig.worker.json`

```jsonc
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "types": [],
    "lib": ["ES2022", "WebWorker"],
    "noEmit": true
  },
  "include": ["src/server/worker.ts", "worker-configuration.d.ts"]
}
```

跑 `pnpm wrangler types` 生成类型声明；`pnpm typecheck` 主配置不受影响（worker 隔离）。

## 步骤 7：部署 CI

`.github/workflows/deploy-api.yml`：

```yaml
name: deploy-api
on:
  push:
    branches: [main]
    paths:
      - 'dist/index.json'
      - 'tools/src/server/**'
      - 'tools/wrangler.jsonc'
      - '.github/workflows/deploy-api.yml'
  workflow_dispatch:
permissions:
  contents: read
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: pnpm/action-setup@v4
        with: { version: 10 }
      - uses: actions/setup-node@v5
        with:
          node-version: '22'
          cache: 'pnpm'
          cache-dependency-path: tools/pnpm-lock.yaml
      - run: pnpm install --frozen-lockfile
        working-directory: tools
      - run: pnpm typecheck
        working-directory: tools
      - run: pnpm test
        working-directory: tools
      - run: pnpm wrangler deploy
        working-directory: tools
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
```

> 首次部署前需用户在 GitHub 配置 `CLOUDFLARE_API_TOKEN` 与 `CLOUDFLARE_ACCOUNT_ID` secret。CI 文件本身可先就绪，token 缺失时 workflow 报错但不阻塞代码合并。

## 风险与回退

- **Workers 运行时差异**：若 `env.ASSETS.fetch` 行为与预期不符，回退方案是构建期内联 `dist/index.json` 为 JS 模块（设计文档 2 节方案 B）。
- **Cloudflare token 缺失**：CI 部署步骤会失败，但代码/测试/本地联调不受影响，可先合代码后补 token 单独触发部署。
- **`@hono/node-server` 与 Windows 本地兼容**：需在 Windows 验证 `pnpm server` 能正常监听。
