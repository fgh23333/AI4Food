## 步骤 2：retrieve.ts 规则检索（TDD 核心）

先写 `tests/server/ai/retrieve.test.ts`，覆盖：
- `extractParams("上海陆家嘴粤菜")` -> `{ city: "上海", cuisine: "粤菜" }`
- `extractParams("人均200的火锅")` -> `{ q: "人均200", tag/keyword }`（价位粗映射或不映射，测试明确）
- `retrieve(question, entries)` -> 候选集正确（复用 applyQuery）
- 候选集为空时逐级放宽（去掉 q -> 去掉 tag -> 去掉 cuisine）
- 候选集 > MAX_CANDIDATES 时截断

实现 `ai/retrieve.ts`：
- `extractParams(question, enums): QueryParams` -- 正则/关键词匹配 city/cuisine/keyword
- `retrieve(question, entries, enums): { candidates: IndexEntry[], params: QueryParams }` -- 调 extractParams + applyQuery + 放宽逻辑 + 截断

跑测试确认通过。

## 步骤 3：prompt.ts 提示词构建（TDD）

`prompt.test.ts` 验证：

- `buildDraftPrompt(description, enums): { system, user }`
- 候选集序列化为精简 JSON（id/name/cuisine/price_level/tags/address/notes/rating）

跑测试确认通过。

## 步骤 4：llm.ts LLM 调用封装

`ai/llm.ts`：
- `LlmClient` 接口（`run(input): Promise<LlmOutput>`）
- `createWorkerLlm(ai, gatewayId): LlmClient` -- `env.AI.run(MODEL, {messages}, {gateway})`
- `parseJsonResponse(text): unknown` -- 从 LLM 文本提取 JSON（兼容 markdown code fence 包裹）
- 常量 `MODEL = '@cf/qwen/qwen3-30b-a3b-fp8'`、`GATEWAY_ID = 'eatornot'`

无需单测（薄封装）；真实调用在步骤 9 联调验证。

## 步骤 5：recommend.ts 推荐编排（TDD）

`recommend.test.ts` 用 mock LlmClient：
- 正常：LLM 返回合法 picks -> 响应含 picks + answer + candidates_considered
- LLM 返回不存在的 id -> 丢弃该 pick，不报错
- LLM 返回非法 JSON -> 抛 LlmResponseError（路由层转 502）
- 候选集为空 -> 响应 answer="未找到匹配餐厅"，picks=[]

实现 `ai/recommend.ts`：
- `recommend(question, entries, enums, llm): Promise<RecommendResponse>`
- 流程：retrieve -> buildPrompt -> llm.run -> parseJson -> 校验 id 存在性 -> 组装响应

跑测试确认通过。

---

## 步骤 6：draft.ts 草稿编排（TDD）

`draft.test.ts` 用 mock LlmClient：
- 正常：LLM 返回草稿 JSON -> 后端校验枚举 -> 响应含 draft + warnings
- LLM 输出 cuisine 越界 -> 置默认"其他" + warning
- LLM 输出 id 与现有冲突 -> 加后缀 + warning
- 必填字段缺失（address/phone）-> warning

实现 `ai/draft.ts`：
- `draft(description, entries, enums, llm): Promise<DraftResponse>`
- 枚举校验、id 唯一性（复用 check-unique 逻辑）、必填字段检查

跑测试确认通过。

## 步骤 7：hono.ts 挂路由 + CORS

改造 `createApp(loader, llm?)`：
- 加 `app.post('/api/ai/recommend', ...)` -> 解析 body -> `recommend(...)`
- 加 `app.post('/api/ai/draft', ...)` -> 解析 body -> `draft(...)`
- CORS 中间件：允许 `https://fgh23333.github.io` 与 `http://localhost:*`，处理 OPTIONS 预检
- 参数校验：question/description 非空且 <= 500 字，否则 400

`hono.test.ts` 扩展：mock loader + mock llm，测 recommend/draft 路由的 200/400/502。

> Node 端 `pnpm server` 无 AI binding，llm 参数缺省时 AI 路由返回 503（"本地未配置 AI"），不影响只读端点。

## 步骤 8：worker.ts 接 env.AI

```ts
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const app = createApp(
      createWorkerLoader(env.ASSETS),
      createWorkerLlm(env.AI),
    )
    return app.fetch(request)
  },
}
```

跑 `pnpm worker:typecheck` 确认类型。

## 风险与回退

- **Qwen3 JSON 模式**：若步骤 9 发现 qwen3-30b 不支持结构化 JSON 输出，退化方案：(a) 换 `@cf/zai-org/glm-4.7-flash`（中文更强，略贵）；(b) 提示词强约束 + 后端正则提取 JSON。设计文档已记。
- **CORS**：若前端跨域预检失败，检查 hono CORS 中间件是否覆盖 OPTIONS。
- **成本**：wrangler dev 联调会产生微量 Workers AI 计费（postpaid），可接受。
